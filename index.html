Оптимизация очереди задач: Redis Streams или RabbitMQ?

Тема создана bytewitch · Сегодня, 09:14 · 1 248 просмотров

Нужно обработать около 50–80 тысяч фоновых задач в сутки. Сейчас используется простой список Redis, но хочется получить нормальные подтверждения, повторную доставку и наблюдаемость.

Выбираю между Redis Streams и RabbitMQ. Команда небольшая, лишний сервис поддерживать не хочется. Текущий обработчик выглядит так:

worker.py
async def consume(redis, stream):
    while True:
        messages = await redis.xreadgroup(
            groupname="workers", consumername=HOST,
            streams={stream: ">"}, count=20, block=5000
        )
        for message_id, payload in unpack(messages):
            await process(payload)
            await redis.xack(stream, "workers", message_id)

Критично не потерять задачу при падении обработчика. Какой вариант выбрали бы для такой нагрузки?

bytewitch написал:

Команда небольшая, лишний сервис поддерживать не хочется.

При такой нагрузке Streams вполне достаточно. У вас уже есть Redis, а consumer groups закрывают подтверждения и повторное чтение сообщений. Обязательно добавьте reclaim зависших задач через XAUTOCLAIM.

Если обработчик находится в PHP-приложении, подтверждайте задачу только после успешной транзакции. Для повторных попыток сохраняйте число попыток отдельно.

worker.php
final class QueueWorker
{
    public function handle(Message $message): void
    {
        $this->connection->transactional(
            fn () => $this->processor->run($message)
        );
        $message->ack();
    }
}
